## 総評

外枠の移植精度は高い。シェルのグリッド（56 / 288 / minmax(560px,1fr) / 308px）、TopBar 52px・PatientBar 54px・AIストリップ 32px・レンズバー 40px、pal-muted の基礎15トークン、Guguru の数値フォントまで、寸法と色は値レベルでモックと一致している。体感9割。

残り1割にモックの中核が集中している。①1本の時系列文書の中身（タイムラインガター、ブロック種別、全文折畳）、②意味色の一貫性、③画面間の連動。これに加えて、医療安全に関わるバグが数件ある。以下、先に塞ぐべき問題、構造的な差分、領域別の全所見の順に記す。

## 1. 先に直すべき問題

### 1-1. 禁忌警告が出ても処方が確定できる（最優先）

- 該当: `frontend/src/components/chart/work/OrderComposer.tsx:187-231`
- モック根拠: 1619-1620・1640・1662行

モックは禁忌時に「処方できません（禁忌）」でボタン無効化＋確定処理内ガードの二重防御。実装の確定処理は安全チェック結果（level: 'bad' ＝アレルギー該当）を一切参照せず、赤警告が表示されたまま Enter で処方が通る。EMR として最優先で塞ぐ。

### 1-2. 架空バイタルを実患者に無表示で差し込む

- 該当: `frontend/src/components/chart/shell/InpatientVitalsBand.tsx:13-21,81`

入院経過が1日分以下のとき、固定のデモ値（7/10〜7/16）を温度板バンドに描画する。実データとの区別が画面上に出ないため、フォールバックであることの明示か、フォールバック自体の削除が必要。

### 1-3. 過去カルテの「S/O 全文」フォールドが展開しても空

- 該当: `frontend/src/components/chart/sheet/streamModel.ts:249-278`、`frontend/src/components/chart/sheet/DayBlock.tsx:204-216`
- モック根拠: 2157-2167・2370-2378行

`buildVisitBlocks` が `soap` を設定しないため、フォールドは矢印が回るだけで中身が出ない。根因は API の `ChartHistoryEntry`（`frontend/src/types/workflow.ts:123`）が date / department / title / summary しか持たず、SOAP 全文を運べないこと。foldLabel の「処方詳細」も同様。

### 1-4. ⌘L と「検査を表で」がモックの明文ルールと逆

- 該当: `frontend/src/components/chart/panels/LabsMatrix.tsx:24-27`、`frontend/src/components/ChartWorkspace.tsx:327-329,1064`
- モック根拠: 2176・2423・2441行

モックは ⌘L ＝検査レンズへの切替で、表は「左→右＝古→新、右端が最新」を太字で規定している。実装は別モーダル LabsMatrix を開き、列順は日付降順（最新が左端）。列順が逆の検査表が同一画面に2系統並存している。レンズ側（`ClinicalLensView.tsx`）は正順で忠実なので、直すのはモーダル側か、⌘L の着地をレンズに変えるか。KARTE_UI_SPEC §4.6 由来の意図的差異の可能性はあるが、片方に決める必要がある。

### 1-5. AppShell の「エージェント」ボタンが補助情報ペインの開閉に配線されている

- 該当: `frontend/src/components/AppShell.tsx:123-130`
- モック根拠: 1933-1939・1950行

モックでは agent-btn と aid-open は独立した別ボタン。実装（非カルテ側）はエージェントボタンの onClick が aid の開閉トグルで、ラベルと挙動が食い違う。カルテ側 `chart/shell/TopBar.tsx:54-61` は正しい意匠なので、AppShell 側だけの問題。

### 1-6. コンポーザで検索欄が空のとき数字キーが即オーダー発行になる

- 該当: `frontend/src/components/chart/work/OrderComposer.tsx:243-249`
- モック根拠: 2951-2955行

検索欄フォーカス中でも query が空なら 1〜6 で履歴を即実行（発行）する。「12誘導」と打とうとすると最初の1で履歴1番が飛び、数字始まりの検索もできない。モックは入力欄フォーカス外のときだけ数字キーを受ける。

## 2. モックと構造的に違う点（影響の大きい順）

### 2-1. 112px タイムラインガターが無い

モックの時系列文書は、左112px の列に日付・年・種別ラベルを置き、縦レールとドットでつなぐ（本日=アクセント、入院中=太レール。モック 296-307・2028-2041行）。実装の `DayBlock.tsx:70-113` は日付をブロック内ヘッダ行に置く別文法で、ガターの CSS 自体は画像・文書レンズにだけ移植されている（`index.css:124-127`、`ClinicalLensView.tsx:373`）。

### 2-2. ストリームのブロック種別が today / visit / lab の3つだけ

event（ワクチン、予約キャンセル、取込）、image（サムネ＋所見＋読影レポート）、yearfold（年ダイジェスト折畳）、adm（入院の入れ子展開）、ストリーム内 vitals がいずれも未実装（`streamModel.ts:115`、モック 2099-2156行）。モックの佐藤患者では13ブロック中6件がこれらに該当し、履歴の密度が大きく落ちる。

根因は API 側にモックの `blocks` / `labSeries` / `orderTimeline` 相当のデータ形が無いこと。visit の SOAP 全文、ブロック種別、オーダー状態遷移、主要列キュレーションを運べる形が無く、UI 側のハードコード（YAMAMOTO_ORDER_ROWS、fallbackDays、★正規表現など）で穴埋めしている。React 側の小修正では直らない。

### 2-3. 意味色が二重体系

- オーダー種別色: モック値の `--dm-*`（med #2f7268 / test #67589e / img #38788f / proc #a2612d / reha #5e7a45、`index.css:23-32` にレンズスコープで存在）と、旧世代の高彩度 `--domain-*`（#0a7d76 / #9333c4 / #c05600、`styles/theme.css:118-123`、`lib/orderDomains.ts:51-57`）が並存。同じ「検査」がレンズ表内とリスト行アイコンで別の紫になる。画像はモックで独立色だが実装では test に統合。
- 検査高値・低値: `--lab-high` / `--lab-low` が pal-apple の値（#d70015 / #0a5dc2）のままで、モック pal-muted の #b0403a / #2b5f96 は `--lens-lab-high/low` にのみ存在（`theme.css:113-114`、`index.css:19-20`）。赤青がレンズ内外で2種類ある。

### 2-4. 画面によって視覚の世代が混在

外来・連絡・医事/設定の簡易ビューは新トークン（text-text-\*、20px h1）でモックのトーンに揃うが、病棟メインと医事/設定の詳細ビューは旧トークン（solid-gray-\*、blue-900、yellow-50、rounded-8、28px h1）のまま（例: `WardWorkspace.tsx:1465-1501`）。レールで切り替えるたびに別アプリに見える。frontend/CLAUDE.md のレガシートークン禁止とも不整合。第一印象を最も損ねているのはここ。

### 2-5. 画面間の「非同期の輪」が閉じていない

モックの見せ場だった連鎖、すなわち医事の点検 issue→連絡で照会→医師が承認→点検解決→ORCA 送信可、検査室の報告確定→外来キューが「診察可」へ昇格＋通知（モック 2716・2742・3002-3030行）が、各画面ローカルの state とトーストで途切れている。

- 連絡の「承認して病名を追加」がローカル表示のみで医事側の解決に波及しない（`CommunicationWorkspace.tsx:114-132`）
- 医事の「医師へ照会」がトースト止まりで連絡へ遷移しない（`BillingWorkspace.tsx` 点検ブロック）
- 検査室ワークスペースと看護・技師ロールが存在しない（ロールは医師 | 管理者 の2種のみ。`types/workflow.ts:1`、`AppRail.tsx:31-33`）
- 結果到着イベントの機構が無い（ポーリング等は皆無、更新は操作起点の refreshToken のみ。`App.tsx:176-241`）。「昇格後の状態」の描画だけはあるので、イベントと共有状態の配線が残っている

### 2-6. 記載中に画面が全面置換される

モックは本日ブロックがその場で編集状態になり、過去ストリームが下に見え続ける（2055-2070行）。実装は writeMode でレンズバーもストリームも消えて InlineEditor 単体カードに置き換わる（`Sheet.tsx:94-102`）。「画面遷移せず、その場で書く」の体感が半分失われている。未記載時の compose バナー「本日の記載はまだありません／記載を始めるまでカルテは読み取りのまま」（2072-2082行）もシート内に無く、記載開始の入口は PatientBar のボタンのみ。

### 2-7. コンポーザの中身（器はあるが未充填）

骨格（右ドロワー、ワイド切替 920px、キーボード）は良いが、モックが作り込んだ次の3点がほぼ手つかず。

1. 処方カートとマイセット: カート列、開始日（本日/明日/次回）、まとめて処方→行為列一括着地、セット保存/展開/削除、セット展開時の禁忌自動除外（モック 404-421・1536-1568・2447-2497行）。ワイドの側列は「よく使う・履歴」であり、カートではない。
2. 4段安全表示: block / warn / ok / info の4段（実装は bad / warn の2段）、「✓ 該当なし」のok行、代替提案ボタン、腎機能に合わせた用量提案、同効薬重複や併用注意のチェック（モック 1492-1520行）。実装済みはアレルギー照合と eGFR<60×NSAIDs 注意のみ。
3. 検査レポートペイン: 発行→採取→測定→技師確定の rep-chain、原本本文（モック 422-434・1677-1735行）。オーダーレンズの「結果到着 ›」の › は現状飾りでクリック不可。

処方フォームも簡素（用量チップ 0.5/1/2/3、用法チップ、日数チップ、処方文プレビュー＋総量、頓用の「n回分」切替が無く、select＋フリーテキストの2欄）。

## 3. 低優先の差分（まとめ）

- 本文最大幅が画面ごとにバラバラ（外来 1060 / 医事簡易・連絡・設定簡易 860 / 病棟 1440 / 詳細系 1600px）。モックは全ビュー 920px 統一。
- 「診察を終了」がモックの次患者自動オープン（トーストで「次: ◯◯」）ではなく、次回予約ダイアログ→受付一覧へ戻る。入院中の「退院処理へ」誘導も無い。
- レールボタンの hover が `bg-surface-subtle`（＝canvas 色）で白カード上ではほぼ見えない。モックは `--sel` #f0eee8。対応値は theme.css に定義済みで未使用。
- コンテキストペインの患者アバターが性別で水色/桃色に塗り分け（12個の直書き hex）。モックは中立 `--kbg` 単色。「原色を避け長時間閲覧に耐える」方針と緊張関係。
- AppShell 側トップバー検索が max-w-2xl（672px）でモックの 400px を超過、⌘K ヒントも kbd 意匠でない（カルテ側 TopBar は 400px＋Kbd で忠実）。
- 病棟の6タブ詳細（概要/指示・記録/経過表/文書/退院・会計/病床）は「時系列はスクロール、タブで隠さない」の文法と衝突。病棟メイン内の「患者を選ぶ」アコーディオンは左コンテキストペインと二重ナビゲーション。
- 入院文脈（温度板バンド）が「病棟から開いた場合」だけ渡る導線依存（`App.tsx:455-457`）。連絡や医事から同じ患者を開くと温度板が出ない。
- 外来「対応が必要」に一部結果の患者も混入（モックは結果が揃った患者のみ）。コンテキストの「最近開いたカルテ」節が無い。
- 連絡の引用カードが汎用チップに退化し非自分メッセージ全件に一律表示。msg-sys（システムメッセージ）とチャンネルへの結果到着通知が無い。
- 医事の解決文言が「医師の確定待ち」（モックは「確定者: あなた」で即解決）。コンテキストに「返戻・査定」節が無い（詳細ビュー側にはある）。
- aid ペイン: 連絡でスレッド固有の患者・請求 issue 情報が出ない（activeThreadId 未受渡）。医事の件数がハードコードで解決状態に追従しない。設定・連絡でも aid を出す（モックは非表示）。
- パンくずが「病棟 / 入院担当患者」等の固定で、メインの切替に追従しない（`AppShell.tsx:105`）。
- 検査レンズ: 初期スクロールが右端（最新）に寄らない。「主要列」がモックの節目キュレーション（初診・入院・健診の key フラグ）でなく単純な直近6列。
- 処方レンズ: 副文「Do は1クリック · 新規は PMDA チェック付き」、履歴行の 開始 / Do n回目 タグ、省略行のクリック展開、PMDA 注記が欠落（骨格と前回Do/まとめてDoは一致）。
- 画像・文書レンズの対象が入院文書のみで外来患者は常に空。image ブロックが無いため imagingOrders があっても出ない。
- ストリームの検査ブロックが全項目グリッド常時表示（モックは ★3〜5項目＋基準値＋「ほか n項目」折畳）。
- カレンダー索引が受診日のみ（検査・画像・入院月が出ない）。yearfold のグレー月＋自動展開なし。
- month-float が「すべて」以外のレンズでも出る。stream-end 注記がシート枠内（モックは枠外）。「ビュー: 医師標準」チップがロール無視の固定。
- ⌘O がトグルでなく開くのみ。病棟ワークスペースにキーボード操作（↑↓ベッド移動）が無い。コンポーザ幅 560px（モック 440px。wide 920px は一致）。
- 空クエリで候補一覧を出さない（モックは履歴＋全候補を常時表示）。画像・処置は正規表現ゲート（XP、CT 等の語）を通らないと出ず、部位名だけではヒットしない。
- 行為列に「未送信」状態の表現が無い（新規バッジはある）。
- トークン残置: `--chart-1..5` / `--sidebar-*` / `--warning` に pal-apple 系値。`--accent-line` / `--hair` 相当のグローバルトークン未定義、PatientBar 安全ラベルが hex 直書き（値はモック一致）。モック `--accent`＝青に対し React `--accent`＝#f0eee8（選択灰）の名前衝突にも注意。
- Kbd 意匠の差（11px・二重下線・数値フォント不使用。モックは 10px・--f-num）。トーストが右下スタック（モックは下中央 ink 地白抜き）。
- 細かい px 差の束: レール padding/gap、バッジ寸法、アバター寸法、AiStrip 縦 padding、lens active 文字色、ctx-title など。視覚影響は軽微。
- base.css の既定が root 16px＋letter-spacing −0.012em（モックは body 14px・字間なし）。シェルは明示 px 指定なので実害は小さいが、サイズ未指定のテキストは 16px で出る。

## 4. 忠実にできている点・モックを超えた拡張

一致（値レベル確認済み）:

- pal-muted 基礎15トークンの完全移植、Guguru @font-face と `.num`、シェルグリッドと breakpoints、TopBar/PatientBar/AiStrip/LensBar の寸法、レール 46px ボタン・9px radius・stroke 1.7、prow のグリッド構成と active 左バー、`.btn` の padding と primary hover。
- AIストリップ（1行要約→「全文と根拠 ›」→展開中の代替文言→右端メタ→免責文）は文言レベルで一致。
- 温度板バンド: 「患者に固定」ヘッダ、畳み時の現在値1行、色（--vt-temp #1d4ed8 等）まで忠実。
- 外来ホームの「対応が必要／本日の予約」2段構成、医事の点検→解決→送信ガード（「送信の確定は人が行います」）、設定の8節と監査ログ、aid ペインの画面別出し分け。
- 書き込みフロー: E 起動、／コマンド、@差込、自動保存3秒、「書き終える ⌘⏎」、行為列、アドライン文言。

モックが「React 実装対象（モック外）」と逃した部分の実装・拡張:
