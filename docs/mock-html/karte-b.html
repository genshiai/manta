読む — View（1カラム・既定）カラムは既定で非表示。常時いるのは患者バーと、1行のAIサマリーだけ。

1カラムが既定の理由

シート自体が文脈を運ぶ — 過去はスクロール、行為と点数は日ブロックの中、検査は流れの中に着地する。だから画面レベルの常設カラムは仕事を失っている。B の思想（読む物としてのカルテ）を貫くなら、既定は最も静かな1カラム。

常時は 2 つだけ

①患者バー（氏名・アレルギー — 患者取り違え防止の安全要件。英NHSのCUIガイドラインも患者バナーの常時表示を要求）②1行AIサマリー（34px） — 「簡易サマリー常時」の要望はこの帯で満たし、「全文と根拠 ›」で展開する。Epic Storyboard が担っていた役割の承継先。

提案はバッジに畳む

エージェントは右上の「✦ 3」バッジに集約し、⌘J かクリックでオーバーレイ召喚。禁忌などの安全警告だけはシート内のインラインバナーとして割り込む資格を持つ。カレンダー・検査表・並べるはシートヘッダのチップから。

並べる — ピン留め3カラムは「状態」ではなく「個人の選択」。オーバーレイをピンで常駐化した姿。

overlay-first, pin optional

Notion のサイドバー・IDE のパネルと同じ文法: 面は召喚が基本、ピンで柱になる。ピン状態はユーザー×ロールで永続化し、⌘\（サマリー）と ⌘J 長押し（エージェント）で切替。既定はあくまで1カラム。

誰がピンするか

ワイドモニタの外来医、返戻点検のようなレビュー作業、そして病棟の看護（温度板・指示を常駐させたい）。デュアルモニタ文化（参照は別窓）の受け皿でもある。

2号紙の継承はここでも

各日ブロックは左=記述（15px）・右=行為+点数（12px）の2カラム — デジカルの本日カルテと同じ、日本の医師の最深部の手癖。ピンの有無に関係なくシートの中身は不変で、学び直しが発生しない。

カラムは何本が正しいのか

結論: EMR の通常は多ペイン、モダン文書ツールの通常は「1カラム + 召喚」。Manta は後者を既定にし、前者をピン留めとして残す。

EMR の通常 = 多ペイン
デジカルは3ペイン、blanc は4面、Epic は Storyboard 常駐。理由は①臨床は参照が多い ②患者バナーの安全要件。ただしこれは「参照を並べたい」への解であって、カラム常設そのものが目的ではない。
モダンの通常 = 1カラム + 召喚
Notion・Craft・Linear の peek・ChatGPT — 内容が1本、面は要るときに現れて消える。「読む物」を作るツールはすべてこちら側にいる。カルテ=読む物、という B の定義に従うならこちらが正。
Manta の答え = 1 + ピン
既定1カラム。多ペインの果たしていた役割は ①安全→患者バー ②サマリー→1行AI帯 ③参照→⌘L等のオーバーレイ ④常駐したい人→ピン留め、に分配して継承する。ロールが既定ピンを決める（病棟看護=温度板ピン）。

2つの文法を固定する

画面がどれだけ増えても、この2つだけ守れば Manta は Manta であり続ける。

「／」の文法（SmartPhrase の教訓）

／ = コマンド・ブロック挿入（オーダー・シェーマ・テンプレ・AI）／ @ = データ差込（@検査値・@バイタル・@薬剤リスト）／ ⌘O = どこからでもコンポーザ。
辞書は「自分の」と「施設の」の2層で、施設辞書は管理画面から中央更新。展開後の穴埋め（用量▾・日数▾）を残せる。テキスト欄ならどこでも同じ記法が効く。

AI の置き場は 4 つだけ

①常時: 左レールのAIサマリー（根拠つき・自動更新）②提案: 右トレイのカード（承認/却下、確定は医師のみ）③召喚: ／のAI項目と ⌘J の依頼 ④随伴: 録音→下書き→レビューのスクライブ。
面を占有するのは①だけ。②〜④は要るときに現れて消える。「AI ready」のような飾りバッジは置かない。

実装ステップ（現行コードからの道順）

シート化 → コンポーザ → ／ → 左レール → スクライブ → 入院、の順で6段。

  1. シート化 — RecordPane の8ビューを1本のストリームに統合。日ブロックを「記述｜行為」2カラム化（行為データは既存の4オーダーAPI+点数）。タブ撤去。
  2. ⌘O コンポーザ — 現4タブDialogを置換。既存の薬剤検索・セット・PMDA警告APIをそのまま裏に。履歴はまず「この患者のDo」から。
  3. ／メニュー — SoapEditor に統合（最近・オーダー・@差込・AI）。コンポーザと同じ検索基盤を使う。
  4. 左レール Storyboard 化 — PatientPane を再構成。AIサマリーはまずルール生成（プロブレム+直近検査+受診理由の整形）で出し、LLM は後から同じ枠に。
  5. スクライブ — 録音→下書き→レビューの器（Write右レール）。生成は既存のAI下書きAPI → LLM 接続へ。
  6. 入院ブロック + 温度板 — WardWorkspace の経過表データを SVG 温度板に。入院をストリームの1ブロックとして外来と接続。

Manta UI Direction v2 — 患者・数値はすべて架空のデモデータ。配色・角丸・タイポは frontend/src/styles/theme.css（Apple HIG / ADR 0003）の実トークン。温度板の配色は看護教材（厚労省掲載）の標準（体温=青・脈拍=赤）に準拠。閲覧ページはライト/ダーク両対応だが、臨床画面（モック内）はライト基調で固定 — 病棟・診察室での受け入れ性を優先。
