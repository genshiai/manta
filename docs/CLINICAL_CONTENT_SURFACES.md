# 臨床コンテンツの表示・編集面

**Status:** Proposal（モック検証用）

## 一つの原則

患者について起きたことは、種類にかかわらず**一つの時系列ストリーム**で読む。種類ごとに別のダッシュボードや常時タブへ分断しない。

「イベント」は独立タブではなく、このストリームの中身である。必要なときだけ `すべて / 記録 / オーダー / 処方 / 検査・処置 / 文書` の**レンズ**で同じ時系列を絞り込む。これにより、たとえば採血の依頼・実施・結果と、その前後の看護記録を時間関係のまま確認できる。

| 種類 | ストリームでまず見せるもの | 詳細・編集の面 | モーダルにしない理由 |
|---|---|---|---|
| 医師・看護師の自由記述 | 時刻、記録者、短い要約、署名状態 | 同じ画面のインライン展開または右の詳細面 | 前後の経過を読みながら参照・追記するため |
| 処方 | 薬剤名、用法、開始・変更・中止 | 右の詳細面。新規・変更はオーダー作業面 | 継続期間と変更履歴を時系列と切り離さないため |
| オーダー | 内容、依頼時刻、実施・結果の状態 | 右の詳細面。新規入力はオーダー作業面 | 依頼→実施→結果という状態遷移が主情報のため |
| 正式文書 | 文書名、下書き/署名済み、作成者、更新時刻 | 専用の文書編集面または右のプレビュー面 | 退院サマリなどは長文・署名・版管理を要するため |
| バイタル・検査 | 最新値、異常、推移 | 同じストリームの展開または表・グラフ面 | 日時との対応と傾向が判断の核になるため |

## モーダルを使う条件

モーダルは、元の時系列を一時停止しても安全で、短時間に完結する作業だけに限定する。

1. 新規オーダーの検索・構造化入力・安全確認
2. 署名、取消などの確定操作
3. 複数日の検査値を比較する表
4. 印刷・提出用の最終プレビュー

自由記述の読解、処方・オーダーの確認、文書の閲覧はモーダルにしない。モーダルを重ねるほど、患者の時間的文脈と患者同定を失いやすくなる。

## 統一された行の文法

すべてのストリーム行を次の順で表示する。

`時刻 → 種別アイコン → 主題 → 1行の状態/要約 → 詳細を開く`

色は、患者安全・異常値・エラーだけに使う。記録、処方、オーダー、文書の区別はアイコンと見出しで行い、色付きチップを増やさない。

## いまのモック

[`mock-html/operations-workspace-prototype.html`](mock-html/operations-workspace-prototype.html) の病棟で、患者を選択すると次を同じ時系列として表示する。

- 看護の自由記述
- オーダー
- 処方
- 退院サマリ
- バイタルの推移グラフと数値表

体温・脈拍・血圧（収縮期）・SpO₂ は個別の小グラフとして表示し、それぞれをオン・オフできる。異なる単位を同じY軸に重ねず、値の取り違えを防ぐ。

記載はすべて架空データである。実装前に、各型のAPI、署名権限、版管理、オーダーの状態遷移を対応付ける。
