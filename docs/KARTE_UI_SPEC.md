- **Status**: Accepted（[ADR 0006](decisions/0006-karte-document-ui.md)）

- **ビジュアル正本**: [`docs/mock-html/karte-b.html`](mock-html/karte-b.html) — ブラウザで開き、5画面 + AIサマリー4パターンを必ず確認してから着手すること
- **スコープ**: カルテ画面（外来・入院）。受付/レセプト/設定の同文法再設計は**別スペック**（未着手）
- **前提知識**: [ADR 0006](decisions/0006-karte-document-ui.md) → 本文書 → モック → `frontend/CLAUDE.md`（トークン・コンポーネント規約）の順で読む

## 1. 決定サマリー（何を作るか）

カルテを**1本のスクロール文書（シート）**にする。診察・検査・処方・画像・文書・**入院**までが1本の時系列ストリーム。タブは廃止し、絞り込みは「レンズ」のみ。画面は3つの状態を持つ：

| 状態 | 入り方 | 出方 | 何が起きるか |
|---|---|---|---|
| **View（読む）** | カルテを開いた既定 | — | シートをスクロールして読む。1カラム |
| **Write（書く）** | `E` / 「＋本日の記載」/ 本日ブロッククリック | `⌘⏎` 書き終える / esc | 本日ブロックが**その場で**エディタ化。／と@が使える |
| **Work（作業）** | `⌘O` / ／からのオーダー系 / 行為列の「+」 | ⏎確定 / esc | コンポーザが文脈の上に浮かぶ。確定物はシートの行為列に着地 |

カラムは既定で非表示。常時表示は**患者バー**と**1行AIサマリー帯**だけ。左右パネルは召喚式＋ピン留めで常駐化できる。臨床画面は**ライト基調で固定**。

## 2. 変えてはいけない原則（ガードレール）

実装中に迷ったらこの表に従う。違反する実装は受け入れない。

1. **タブ復活禁止** — 時系列・履歴をタブで隠さない。切替はレンズ（絞り込み）のみ
2. **1面に塗りボタンは1つ** — View/Writeでは「診察を終了」「書き終える」だけがピル型プライマリ。行の動詞は hover の「⋯」メニューへ
3. **AIは確定しない** — 生成物・提案には必ず「候補」「下書き」バッジ+根拠+免責。カルテ・会計の確定操作は医師のみ（ADR 0004）
4. **臨床画面ダーク禁止** — カルテ・温度板コンテナに `.dark` を伝播させない（§9.1）
5. **多色は臨床データ専用** — アクセントは `--brand`（#0071e3）1色。検査H/L・安全警告・温度板だけが追加色を使える
6. **レガシー禁止** — `solid-gray-*` / `text-mono-*` / `text-std-*` / `vendor/dads` / `lib/cn` を新規コードで使わない
7. **モーダル最小** — 許されるオーバーレイはコンポーザ（⌘O）・⌘K・⌘J・⌘L検査表・印刷系のみ。確認ダイアログの連打で業務を止めない
8. **点数は行為の影** — 行為列の下に常時表示。会計はカルテの派生データ（ADR 0004）を毎日視覚化する
9. **キーボードで完結** — §10 のキーマップを全実装。ポインタ必須の操作を作らない
10. **数値は tabular-nums** — 検査値・点数・時刻・ID すべて

## 3. 画面シェル仕様（寸法）

```
┌ AppRail 56px ┬──────────────────────────────────────────────┐
│ M ロゴ 30px  │ TopBar 52px: 戻る+パンくず / ⌘K検索(max400) /  │
│ 外来(on)     │              エージェント✦N / アバター28        │
│ 病棟         ├──────────────────────────────────────────────┤
│ 医事         │ PatientBar 50px: 氏名16bold+カナ10.5+メタ12 /   │
│ ---          │   アレルギーchip(bad) / 保存状態 / [＋本日の記載 E]│
│ 設定         │   [診察を終了]（唯一のピル型プライマリ）          │
│ アバター     ├──────────────────────────────────────────────┤
└──────────────│ AIStrip 34px: ✦ 1行サマリー … [全文と根拠 ›]    │
               ├──────────────────────────────────────────────┤
               │ SheetHead 42px: レンズ(すべて/診察/検査/処方/    │
               │   画像・文書) … [カレンダー][検査を表 ⌘L][並べる ⌘\]│
               ├──────────────────────────────────────────────┤
               │ SheetScroll（唯一のスクロール領域）              │
               │   └ Sheet max-width 884px 中央寄せ              │
               └──────────────────────────────────────────────┘
```

| 要素 | 値 |
|---|---|
| App ルート | `h-screen overflow-hidden`（全体スクロール禁止・既存方針継続） |
| レール | 56px 固定。アイコン 38×38、active は `bg-brand-tint text-brand` |
| TopBar / PatientBar / AIStrip / SheetHead | 52 / 50 / 34 / 42 px、いずれも `border-b border-border bg-card` |
| シート | `max-width:884px`（入院の温度板表示時のみ 1096px）。`bg-card border border-border rounded-t-xl`、**影なし**（境界線ファースト） |
| ピン展開時 | 左パネル 296px / 右パネル 332px（§7）。シートは残り幅で中央寄せ |
| 月フロート | シート右上に `2026年7月` のピル（sticky、スクロール位置の月を表示） |

## 4. View（読む）仕様

### 4.1 ストリームとブロック種別

シートの子は `DayBlock` の縦列。**新しい日付が上**。ブロック種別：

| 種別 | 中身 | 備考 |
|---|---|---|
| 診察（外来） | 日付ヘッダ + 2号紙2カラム（§4.2） | 本日ブロックは `border-l 3px brand` + 「本日」chip |
| 検査結果 | 検査グリッド（3〜6列、H/L色つき） | 単独ブロック。診察に紐づく採血も独立表示 |
| 入院 | §8 の入院ブロック | ストリーム内に埋まる |
| 画像 / 文書 / 予約 | コンパクト1行〜数行 | 折畳既定 |

- 過去ブロックは **A/P要約 + 行為サマリのみ常時表示**、S/O全文・処方詳細・検査全項目は折畳（`▸ S/O 全文 · 検査 6項目`）。既存方針（副情報デフォルト折畳）を継続
- ストリーム末尾に `↓ 2021年8月の初診まで続く（全 N 件）`。無限スクロール（ページング取得、1ページ=10ブロック目安）
- 展開状態はセッション内保持

### 4.2 日ブロック = 2号紙の現代化（最重要コンポーネント）

```
┌ DayBlock ──────────────────────────────────────────────┐
│ day-h: 7/4（土）09:41 [本日] 定期再診·内科·田中·v2  … ⋯ │ padding 11px 20px
├──────────────────────────────┬─────────────────────────┤
│ day-main（記述）              │ day-acts（行為）232px    │ grid: 1fr 232px, gap 18px
│  S/O/A/P 行:                 │  ラベル10.5px+「+」      │ 左padding 20px
│   キー22×22 rounded bg-mut   │  行: 薬剤名12px/600      │ 行為列は border-l で分離
│   本文 14.5px/1.75           │      用法11px t3         │
│   バイタルchips 12px tabular  │  ⚠警告行 11px warn      │
│   検査グリッド bg-sub r8      │  ─ 点数行(border-t破線): │
│                              │  再診75+管理225+処方60   │
│                              │  **360点** 右寄せ        │
├──────────────────────────────┴─────────────────────────┤
│ addline: ［／］追記・オーダー・病名・文書 — ／か⌘Oで      │ 本日ブロックのみ
└─────────────────────────────────────────────────────────┘
```

- 行為列の項目は **hover で「⋯」**（編集/取消/コピー）。新規追加分は `新規` chip（tint）
- 行為列の点数は§12の算定プレビューAPIから。取得失敗時は「—点」表示で診療を止めない

### 4.3 レンズ

`すべて / 診察 / 検査 / 処方 / 画像・文書` の絞り込みピル（`.lens`、active=`bg-text text-bg`）。場所の移動ではなく**同じストリームのフィルタ**。レンズ切替でスクロール位置は先頭へ。

### 4.4 AIサマリー（2状態 + 表示形式）

**状態遷移**（同一コンポーネント）:

```
初回オープン（当日初 or 前回閲覧から7日超） → B: AIOカード（シート先頭に展開）
   └ 「畳む」/ スクロール開始 → A: 1行ストリップ（34px帯）に畳まれる
   └ A の「全文と根拠 ›」 → B に再展開
```

**B: AIOカード**（既定の展開形。モックの「B AIOカード」参照）
- 枠: `border 1px color-mix(in srgb, var(--brand) 28%, var(--border))`, `border-radius 13px`, `background: linear-gradient(180deg, var(--brand-tint), var(--card) 55%)`
- ヘッダ: ✦アイコン24px + 「AIサマリー」13px/700 + メタ「直近N回の診察・検査から · HH:MM 更新」11px + 👍👎 + 畳む
- 本文: 13.5px/1.8、太字はキー所見のみ（HbA1c推移・新規訴え・腎機能・入院歴）
- 右列 236px: 「根拠」カード3枚（日付+種別 bold / 1行要約）。クリックで該当ブロックへスクロールジャンプ
- フッタ: 免責「AIによる要約です。診療上の判断は原本を確認してください。」+ 右「この患者について質問 ⌘J」
- **C（定型4行ブリーフィング: 管理中/変化/本日/注意 + 出典チップ）は本文形式のユーザー設定**（散文=既定 / 定型行）。**D の追い質問チップは B のフッタ上に1行で同梱**（最大4個）

**A: 1行ストリップ**: `✦ [要約1行 ellipsis] — 全文と根拠 › | ✦ AIサマリー · 生成範囲 · HH:MM`

**生成コントラクト（§13 と対応）** — UIはこのJSONだけを見る:
```json
{
  "one_liner": "高血圧・糖尿病で通院中。HbA1c 7.0→7.2 微増・本日右膝痛の新規訴え・eGFR 58でNSAIDs慎重",
  "paragraphs": ["…", "…"],
  "briefing": {"managing": "…", "change": "…", "today": "…", "caution": "…"},
  "evidence": [{"date": "2026-07-04", "kind": "lab", "label": "HbA1c 7.2 ↑ · eGFR 58.3 ↓", "block_ref": "…"}],
  "generated_from": "直近14回の診察・検査", "generated_at": "…", "engine": "rule|llm"
}
```

### 4.5 カレンダー = シートのインデックス

左パネル（ピン時）または SheetHead「カレンダー」チップのポップオーバー。月グリッド + 受診日ドット + 年チップ（2026/2025/2024）。**日付クリック = その日のブロックへスクロールジャンプ**（該当ページ未取得ならフェッチしてから）。

### 4.6 検査を表で見る（⌘L）

同タブのオーバーレイ（e2影・幅~1100px）。行=検査項目 × 列=日付降順のマトリクス、先頭列とヘッダ sticky、異常値は `--lab-high/--lab-low` 色+H/L記号。項目チェックで選択→「推移グラフ」。データは既存の検査トレンドAPI（§12）。※blanc `lab.html` の sticky グリッドパターンを踏襲

## 5. Write（書く）仕様

### 5.1 その場展開

- 本日ブロックがシート内でエディタ化（`border-color: border-strong`、レール以外の chrome は薄く）。**画面遷移・全画面モーダルにしない**
- 左パネルは自動で畳まれ 56px のアイコン帯（患者/⚠/✦/暦）。右は「書く道具」トレイに切替（§5.4）
- TopBar 右が `自動保存 · vN · HH:MM` + **[書き終える ⌘⏎]** に変わる
- 自動保存: 3秒 debounce で下書き保存。「書き終える」で版確定（既存 `chart/save` の version++ を使用）
- 行為列はライブ: ／・⌘O で追加したオーダーが即座に積まれ、点数も更新

### 5.2 ／メニュー（スラッシュコマンド）

エディタ内で `／` 入力 → キャレット直下にポップオーバー（幅328px、e2影）。**インクリメンタル検索**（「せれこ」→薬剤候補）。

| グループ | 項目 | 挙動 |
|---|---|---|
| 最近・よく使う | この患者の直近3件（前回Do処方 / 検査セット / 前回と同じ画像 等） | **①②③キーで即実行**。表示は名称+前回使用日 |
| オーダー | 処方を検索… / 検査 / 画像 / 処置 | 選択で ⌘O コンポーザへ引き継ぎ（入力文字列を持って開く） |
| 挿入 | `@検査値` `@バイタル` / シェーマ / テンプレート / 病名 | @系は§5.3。シェーマは既存資産があれば流用、なければ Phase 外 |
| AI | 下書き生成（このセクション） / 前回から要約 / 校正 | 生成物は必ず「下書き」バッジつき挿入 |

- フッタ: `↑↓ 選択 · ⏎ 挿入 · ①②③ 最近を即実行 · esc`
- 辞書は「自分の」と「施設の」の**2層**（施設辞書は管理画面から更新）— Epic SmartPhrase 準拠
- ／はテキスト入力欄ならどこでも同じ文法（SOAP各欄・文書エディタ・指示コメント）

### 5.3 @データ差込

`@` でカルテ内データを**構造化チップとして**差し込む: `@検査値`（直近パネルから選択）・`@バイタル`（本日の測定）・`@薬剤リスト`。挿入後は値スナップショット+取得日時を保持（後から値が変わっても記載は不変）。

### 5.4 書く道具トレイ（右 332px・Write中のみ）

上から: ①スクライブカード（`● 診察を録音中 MM:SS` → [停止して下書き] → S/O下書きを**下書きバッジつき**で提示、承認で本文へ）②データを貼るchips（検査異常→O / バイタル→O / 前回A複写）③書きながらチェック（病名未対応 N件 — リアルタイム）④下書きカード（例: HbA1c指導文 → [Pに挿入]）。
録音→生成は Phase 5 では**器のみ**（録音UI+ステート遷移。文字起こし・生成はスタブ、§13）。

## 6. Work（⌘O コンポーザ）仕様

従来のオーダーポップアップの現代解釈。**ページ遷移なし・背景のカルテが `--dim` 越しに見える・キーボード完結・確定はシートの行為列に着地**。

```
┌ Composer 760px 中央, top 96px, radius 14, e2影 ─────────────┐
│ [⌘O] セレコ▌        処方・検査・画像・処置・セット・文書・算定 を横断検索 │
├──────────── 左 252px ────────┬──────────── 右 ─────────────┤
│ よく使う・履歴（この患者）      │ 検索ヒット（選択中は tint 枠）  │
│  1 前回Do処方(3剤·28日) ×12回 │  セレコキシブ錠100mg「サワイ」  │
│  2 生化学+HbA1cセット   ×15回 │  後発 · YJ · 薬価/3割目安      │
│  3 特定疾患療養管理料    毎月  │ 構造化フォーム: 1回量/用法/回数  │
│ よく使う（あなた・全患者）      │ ⚠ eGFR 58 慎重投与(PMDA 8.1)   │
│  4 カロナール500 3T分3  週8回 │ ☑ 病名「変形性膝関節症(右)」を   │
│  5 かぜセット           週5回 │    同時に追加する               │
│  6 胸部XP 2方向         週4回 │                               │
├──────────────────────────────┴───────────────────────────────┤
│ ⏎ 追加して閉じる · ⇧⏎ 続けて追加 · 1–6 履歴を即実行 · esc      │
└──────────────────────────────────────────────────────────────┘
```

- **履歴が検索より先**: 左列は「この患者」（Do・定期セット・毎月の算定）と「自分（全患者）」の2層。使用回数を表示し、**数字キー1発で再実行**
- 型推論: 「アムロ」→薬剤 / 「採血」「生化学」→検査セット / 「XP」「X線」→画像 / 点数名→算定。カテゴリピルでの手動絞りも可
- **安全は発行前に同じ面で**: PMDA警告（相互作用・禁忌・腎/妊娠）と適応病名なしをフォーム直下にインライン表示。「病名を同時追加 ☑」で1操作解消。重複処方はここでブロック（既存400エラーを警告行に変換）
- 確定後: View なら本日ブロックの行為列へ、Write ならキャレット位置にオーダーチップ+行為列の両方へ

## 7. 並べる（ピン留め）仕様

- 文法: **overlay-first, pin optional**。`⌘\`=左パネル、`⌘J`=右トレイ（クリック=オーバーレイ、ピンアイコン=常駐）
- 左パネル（296px）: 患者基本（38pxアバター+氏名+生年月日/保険/主治医）→ AIサマリー全文カード → アレルギー → プロブレム（ICD10 chip、`+`で病名検索）→ ミニカレンダー+年チップ
- 右トレイ（332px）: ヘッダ（✦ エージェント · 文脈表示）+ プラン要約ストリップ（処方4·検査1·画像1·360点）+ 提案カード列 + 依頼入力 + 免責
- 提案カードの構造: アイコンバッジ24px（warn/bad/acc/ok）+ タイトル12px/700 + 根拠11px + アクション行（プライマリゴースト+却下+右端に候補/注意/下書きバッジ）。**1診察あたり表示は重要度順で最大5件**。承認済みは opacity .6 + ✓
- ピン状態は `localStorage`（キー: `manta-panel-pins:{userId}:{role}`）。既定: 外来医師=両方OFF / 病棟看護=左OFF・温度板ピンON / 事務=右（会計派生）ON
- エージェントのバッジ（TopBar `✦ N`）は未処理提案数

## 8. 入院（温度板）仕様

### 8.1 入院ブロック

入院は**ストリームの1ブロック**（外来と同じシート・同じ文法）。ヘッダ: `入院 2/10（火）– 2/17（火） [市中肺炎 · 7日間] 3F 302 · 主治医`。内部レンズ: `温度板(既定) / 経過抄録 / 指示 / 看護記録 / 文書`。

### 8.2 温度板（ヒーローコンポーネント）

- **サイズ**: シート幅いっぱい（入院表示時はシート max-width 1096px）。グラフ viewBox 1032×316 相当
- **ツールバー**: `‹ [2/10（火）– 2/16（月）/ 病日1–7 · 横スクロールでも移動] ›` + 期間セグメント `3日/7日(既定)/14日/全期間`
- **軸**: 横=暦日+病日の2段。縦=左軸 体温35–40℃ / 右軸 脈拍40–140。横罫6本・日付縦罫
- **系列（標準配色・変更禁止）**: 体温=`--vt-temp`(#1d4ed8) 折れ線2.6px+点3.6px+**点上に実数値直書き**（11.5px/700）／ 脈拍=`--vt-pulse`(#d70015) 折れ線2px+点3px ／ 血圧=`--vt-bp`(#5e8468) **∨（収縮期）∧（拡張期）を縦線で結ぶ**
- **左端に前期間の線を薄く（opacity .3・破線）覗かせる** = 続きがあるサイン
- **下段グリッド**（`76px + 7等分`、12px tabular）: 体温 / 脈拍 / 血圧 / SpO₂ / 酸素 / 抗菌薬（投与帯=tint帯で連結表示）/ 食事 / イベント（入院・血培・XP・内服へ・退院決定 のchip）
- データ源: §12。1日複数検温は7日表示では代表値（最高体温）、3日表示で全点

## 13. AI実装の段階（差し替え可能に作る）

| 段階 | サマリー | 提案カード | 下書き/スクライブ |
|---|---|---|---|
| **v1（本スペックの完了条件）** | ルール生成（§12 summary API）。`engine:"rule"` | 既存 recheck / PMDA / 処方コピーの出力を整形 | 既存テンプレ下書きAPI + 録音UIの器（生成はスタブ表示） |
| **v2（別タスク）** | 同じJSONコントラクトで LLM に差し替え | LLM による説明文の自然化・優先度付け | 文字起こし+生成（録音→下書き→レビュー） |

**UIは `engine` フィールド以外 v1/v2 を区別しない**こと。これが差し替え可能性の担保。LLM接続時も「AIは確定しない」原則（§2-3）は不変。
