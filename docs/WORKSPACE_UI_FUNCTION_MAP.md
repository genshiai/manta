# ワークスペース型 UI：現機能からの画面設計マップ

**Status:** Proposal（2026-07-14）  
**関連モック:** [`mock-html/workspace-prototype.html`](mock-html/workspace-prototype.html)  
**前提:** 現在の機能を捨てず、操作の入口と優先順位を再設計する。

## 「未処理」「要確認」を独立したタスク概念にしない

`未処理` は状態でしかなく、利用者が次にする行為を表さない。そのため UI の見出し・フィルタには使わない。現行の外来ボードで表示するものは、利用者が登録する汎用タスクではなく、受付状態・検査状態・患者属性から導かれる**患者の現在状態**である。

| 旧い曖昧な表現 | 表示するべき行為 | 実装済み機能との対応 |
|---|---|---|
| システムが検出する状態 | 画面に出すべき事実 | 現行機能との対応 |
| 結果到着 / 一部結果 | 検査結果が到着している患者 | 外来ボード、検査履歴 |
| 同姓同名 | 同名患者が複数いる | 外来ボードの患者取り違え注意 |
| 診察一時中断 | 診察が中断状態にある | 外来ボードの受付状態 |
| 未実施指示 | 実施済みになっていない指示がある | 病棟の指示 |
| 未署名文書 | 署名が必要な文書がある | 病棟の文書、退院サマリー |
| 請求 issue | 請求ドラフトに未解決の問題がある | Claim draft の issue / adjustment |

これらは個別に登録しない。必要なら既存の状態を更新する（例: 検査結果を原本で確認する、診察を再開する、文書へ署名する）。集計値だけの「要確認 3件」にはしない。

## 実装済み機能 → ワークスペースの置き場所

| ワークスペース | いまある機能 | 新しい入口 | 主作業 | 補助情報 |
|---|---|---|---|---|
| 外来 | 受付ボード、検索、患者カルテ、SOAP、オーダー、予約、検査履歴 | 今日の患者 / 検査到着・診察中断・同姓同名 | 本日の記載、オーダー | AI要約、検査、既往、患者情報 |
| 病棟 | ベッド、転棟、看護記録、温度板、指示、文書、退院サマリー、パス | 病床 / ラウンド / 未実施指示・未署名文書 | 看護記録、指示、経過抄録 | 温度板、検査時系列、請求ドラフト |
| 医事 | claim draft、ルール、返戻・査定、月次クローズ、ORCA | 会計待ち / 要修正 / 送信待ち | 人による点検、送信、返戻対応 | AI候補、ORCA payload、監査履歴 |
| 設定 | 利用者、処方候補、セット、予約枠、テンプレート、施設ルール、ORCA設定、監査ログ | 管理対象 | 作成・更新・テスト | 監査ログ、接続結果 |

## フォントの方針

本文をすべて等幅にしない。長い診療記録を読む速度と自然さを優先する。

| 用途 | 推奨 |
|---|---|
| 本文、見出し、ボタン、患者名 | **PlemolJP を第一候補**にしたフォントスタック（モックで全面検証） |
| 患者ID、日時、バイタル、検査値、点数、レセ電コード | PlemolJP の等幅・tabular 数字を使用 |
| コードや機械可読な payload | PlemolJP / monospace |

PlemolJP は IBM Plex Mono と IBM Plex Sans JP の合成フォントで、等幅の数字・記号を扱いやすい。**ユーザー判断により、本文を含めた標準フォント候補としてモックで全面検証する。** 導入時には webfont の配信サイズ、ライセンス表記、全角記号・医学記号の実機確認を行う。

## モックの受入条件

1. 外来のホームで「検査結果を確認」「同姓同名を確認」などの行為が、患者名と一緒に見える。
2. 患者を選ぶと、本日の記載・オーダーが最初に現れる。
3. 病棟・医事・設定は実装済みの機能群をそのまま見つけられる。
4. AI はどの画面でも補助領域に留まり、根拠・原本へ戻る導線を持つ。
5. 色付きラベルは安全注意と破綻状態に限り、通常の状態・分類はテキストで表す。

## 温度板（バイタル・経過表）の意味

温度板は、**入院中の一人の患者について、時刻ごとの体温・脈拍・血圧・SpO₂・摂取排出・処置・経過を横断して見る病棟の表**である。外来カルテの時系列を別名で表示するものではない。新モックでは、誤解を避けるため画面名を「バイタル・経過表」とし、実データの表を表示する。
