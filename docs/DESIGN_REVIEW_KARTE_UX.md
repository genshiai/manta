## 今の位置づけ

Manta はデジタル庁デザインシステム寄りに、余白、フォーカス、ボタン、フォーム、カードの読みやすさを優先している。これは安全性とアクセシビリティの観点では正しい。

一方、外来カルテは「短時間で過去情報を読み、今日の記録とオーダを同時に作る」業務なので、一般的な行政 UI よりも高密度な情報配置が必要になる。blanc や medlocal mock はこの点で参考になる。

## Blanc / medlocal から拾うべき構造

### 1. 常時 3 ペイン構造

blanc 風 UI は以下の流れが明確。

```text
左: 患者情報・履歴・機能ナビ
中央: 選択日のカルテ / オーダ履歴
右: 今日の入力 / オーダ作成
```

Manta は現在、左の患者情報と中央履歴はあるが、右オーダ領域が下方向に流れやすく、画面幅やスクロール位置によって「見ながら入力」が弱くなる。外来用途では右ペインをより固定的に扱うべき。

### 2. 患者コンテキストバー

blanc は上部に患者 ID、氏名、性別、生年月日、保険、警告タグを横並びで常時表示する。Manta も患者ヘッダーはあるが、カード内情報と分散している。

改善方針:

- 画面最上部に患者コンテキストバーを固定表示
- アレルギー、同姓同名、妊娠、感染症、造影剤副反応などの安全タグは常時見える位置に置く
- 受付へ戻る、患者切替、診療科、担当医を同じバーに寄せる

### 3. 履歴リストの強化

blanc は日付リストを左または中央左に置き、日付を選ぶと中央の履歴内容が切り替わる。Manta は時系列参照タブ内では見えるが、カルテ記載中の履歴参照がやや遠い。

改善方針:

- カルテ記載画面でも「直近履歴リスト」を常時表示
- 日付選択で SOAP、処方、検査、画像、文書をまとめて中央に表示
- 現在の「時系列参照」タブは詳細参照として残し、カルテ記載画面にはショート版履歴を置く

### 4. オーダと記録の近接

blanc は中央に過去オーダ、右に新規オーダ/記録入力を置くため、コピーやセット展開の前後関係が見やすい。Manta は処方セット、検査セット、前回複写の機能は増えているが、UI 上は「下にある作業領域」になりやすい。

改善方針:

- 右ペインを「今日の作業キュー」として固定
- 処方、検査、画像、処置、予約をタブ化したまま、プレビュー/確定操作を同じ領域で完結
- 追加済みオーダと追加候補を上下で分ける
- 複写前プレビュー、セット展開前プレビューは右ペイン上部に出す

### 5. 情報密度の調整

Manta はカード単位で読みやすいが、縦方向のスクロール量が多い。外来では「俯瞰できる量」が重要なので、特定領域だけ情報密度を上げる。

上げるべき領域:

- 受診履歴
- 薬歴
- 検査結果
- 処方候補
- セット展開プレビュー

維持すべき領域:

- SOAP 入力
- 警告
- 保存 / 確定 / 削除などのリスク操作
- 管理 UI

## Manta に残すべきデジタル庁デザインシステムの考え方

- フォーカスリング、ラベル、フォーム要素の明確さ
- 危険操作と通常操作の視覚的区別
- テキストコントラスト
- ボタンの階層
- エラー文言の明示
- スクリーンリーダーで理解できる heading / button / label 構造

blanc 風の高密度をそのままコピーすると、アクセシビリティと初見の理解性が落ちる。Manta では「高密度な業務領域」と「明確な操作領域」を分ける。

## 次のデザイン実装案

### Step 1: カルテ画面のレイアウト再編

- 上部に患者コンテキストバーを固定
- 左ペインを患者情報 + 直近履歴に絞る
- 中央ペインをカルテ本文 / 履歴詳細にする
- 右ペインを今日のオーダ / 予約 / 保存アクションにする

実装状況: 2026-04-29 に初期反映済み。`ChartWorkspace` は初期表示を「本日の記載」に変更し、上部に患者コンテキストバー、左に日付単位履歴、右に今日の作業キューを配置した。既存の処方複写、セット展開前プレビュー、検査セット、予約、診察終了の機能は右ペイン内に維持している。

追加改善: 2026-04-29 に、1100px 前後のプレビュー幅でも 3 ペインが崩れないようにレイアウトを再調整した。左ペインは患者コンテキストと直近履歴を圧縮し、中央には直近受診、異常検査、継続処方、作業キュー警告のサマリを追加した。患者を開いた初期状態は必ず「本日の記載」に戻す。

### Step 2: 履歴の「日付単位ビュー」

- 日付ごとに SOAP、処方、検査、画像、文書を一括表示
- 「この日の処方を確認」「この日の検査を確認」「この日から複写」導線を置く

### Step 3: 右ペインの作業キュー化

- 現在処方
- 追加候補
- セット展開前プレビュー
- 複写前プレビュー
- 次回予約
- 診察終了

を同じ右ペインで完結させる。

### Step 4: 検査結果ビューの表形式強化

- 現在のグラフは残す
- blanc のような「日付列 × 検査項目行」の表を追加
- 異常値は DADS の警告色に寄せて、赤/黄の意味を明確化

## 判断

現状の Manta は「行政 UI として読みやすい」が、電子カルテとしてはやや余白が大きく、過去情報を見ながら今日の入力を進める流れが弱い。

次の UI 改善は、見た目の装飾ではなくレイアウト密度と情報の位置関係を直すべき。特に `患者コンテキストバー`、`日付単位履歴`、`右作業キュー` の 3 点が最優先。

## 2026-04-30 決定事項（タブ構造 / カルテ起動方式 / 色味）

### 背景

ユーザーから以下のフィードバックがあり、UI 構造を再設計することになった:

1. **「カルテ作成（診療録作成）は能動的アクション」** — X 投稿・新規作成と同じジャンルであり、デフォルト状態として置くのは概念的におかしい
2. **「上部タブが2つしかないのは UX が最悪」** — 現状の `受付 / 設定` のみでは患者カルテのビュー切替が出来ない
3. **「色味は原色を減らす」** — Apple・Google フラットデザインのように長時間見ても疲れない色味にしたい

### 決定一覧

| 番号 | 項目 | 決定 |
|---|---|---|
| ① | 上部タブの位置 | **B. カルテ画面専用** の上部タブ（受付画面では出さない） |
| ② | 上部タブ項目 | **B. Manta 簡略版**: 履歴 / カレンダー / 検査 / 画像 / 文書 / 予約 / 検索 |
| ③ | カルテ記載エディタの起動 | **A. 「+ 本日の記載」ボタン → 中央ペイン上部に展開** |
| ④ | デフォルト表示 | **A. 履歴タブ**（過去カルテのリスト＝読むビュー） |
| ⑤ | 右ペイン | **C. 「本日のキュー」化**（追加済オーダ一覧 + 「+追加」ボタン → モーダル） |
| ⑥a | カレンダー UI | **B. 左ペインにミニカレンダー常設 + 上部タブで全画面ビュー** |
| ⑥b | カレンダーマーキング | **D. 多色ドット + フィルタ**（カルテ/検査/処方/画像をドット表示、絞り込み可） |
| ⑦ | 色味方針 | **A. Apple HIG（apple.com/jp 実測値準拠）** — `#1d1d1f` テキスト + `#0071e3` アクセント + `#f5f5f7` 背景、SF Pro JP フォントスタック、ピル型ボタン |

### 各決定の理由

#### ① B（カルテ画面専用タブ）
受付画面と混ざると文脈が壊れる。タブは患者カルテを開いた状態でしか意味がない。

#### ② B（簡略版）
blanc の「指導料」「定型」「テンプレート」は Manta 未実装機能。まずは 履歴 / カレンダー / 検査 / 画像 / 文書 / 予約 / 検索 の7タブから始める。

#### ③ A（中央ペイン展開）
モーダル/Drawer だと過去カルテを参照しながら書けない。中央ペイン上部に展開すれば、下にスクロールすれば過去カルテが見える blanc 風の「読みながら書く」が成立する。

#### ④ A（履歴がデフォルト）
**カルテ作成は能動的アクション**（X 投稿・新規作成と同じジャンル）であり、デフォルト状態として置くのは概念的におかしい。患者を開いた最初の状態は「過去の情報を読む」であるべきで、書く行為は「+ 本日の記載」ボタンで明示的に起動する。

#### ⑤ C（右ペインをキュー化）
現状の処方/検査/画像/処置の4タブを右ペインに常時並べるのはノイズが多い。「本日追加されたオーダの一覧」+「+追加」ボタン → モーダルで起動、の方が情報密度が下がる。

#### ⑥a B / ⑥b D（カレンダーは両刀 + 多色ドット）
- 日付即移動のためにミニカレンダーは左ペインに常設
- 月単位俯瞰のために上部タブでフルビュー
- カルテ/検査/処方/画像のイベントを多色ドットで表現、フィルタで絞り込み（一般的なカルテ慣習）

#### ⑦ A（Apple HIG）
- ユーザー本人がモック比較で「APPLE HIG めっちゃいいね」と高評価 (2026-04-30)
- apple.com/jp の実測値（[`design-reference/apple-jp-design.md`](./design-reference/apple-jp-design.md)）に準拠 — Puppeteer による computed style 取得
- 文字色は **`#1d1d1f`**（純黒 `#000` を禁止 → 目に優しい）
- アクセント **`#0071e3`** は CTA / 選択中 / リンクに限定使用（散らさない原則とセット）
- 完全ピル型ボタン（980px radius）、フォーカスリング `0 0 0 3px rgba(0,113,227,0.2)`
- SF Pro JP 先頭のフォントスタック、負のトラッキング `-0.012em` (本文)、`palt` 不使用

#### Apple HIG を **全面採用しない** 部分（EMR 向けに調整）
- Apple のフォントサイズ（17px body / 40px heading）は**そのまま採用しない** — EMR は情報密度が必要なため、本文 14px / 見出し 18-20px に圧縮
- Apple のヒーロー余白（マガジンレイアウト）も**そのまま採用しない** — 3 ペイン + 高密度を優先
- 採用するのは **配色・タイポグラフィ規則・ボタン形状・フォーカスリング・フォントスタック**

### タイポグラフィ規則（A 採用時）

```css
font-family:
  "SF Pro JP", "SF Pro Text", "SF Pro Icons",
  "Hiragino Kaku Gothic Pro", "ヒラギノ角ゴ Pro W3",
  メイリオ, Meiryo, "ＭＳ Ｐゴシック",
  -apple-system, BlinkMacSystemFont, "Helvetica Neue", Helvetica, Arial, sans-serif;

letter-spacing: -0.012em;       /* 本文（負のトラッキング = Apple の特徴） */
font-feature-settings: normal;  /* palt 不使用（SF Pro JP に内蔵） */
```

注意:
- ヒラギノ角ゴは **Pro**（**ProN ではない**）— Apple JP サイト準拠
- 14px 以下のキャプションは `letter-spacing: normal`
- 大見出し（24px+）は `letter-spacing: -0.015em` までやや強める

### ボタン形状（A 採用時）

- **Primary CTA**（保存・診察終了・追加 等）: `border-radius: 980px`（完全ピル型）+ Apple Blue 背景 + 白文字 + ホバーで Link Blue
- **Outline**: `border-radius: 980px` + 透明背景 + Apple Blue 文字 + 1px Apple Blue 境界
- **Dark Fill**（破壊的操作 / モーダル確定）: `border-radius: 8px` + `#1d1d1f` 背景 + 白文字
- **Ghost**（テキストボタン）: 角丸 6px + 透明背景 + ホバーで `--surface-subtle`

### 状態色ルール

- **異常検査** → `--destructive` (`#FF3B30`) + アイコン併用（色だけに依存しない）
- **警告タグ**（アレルギー等） → `--warning-bg` (`#FFF4E5`) + `--warning` (`#FF9500`) 文字
- **正常表示** → 色を使わない（ノイズ削減）
- **アクセント青は限定使用** — 散らさない（選択中の日付・選択中のカルテ・主要 CTA・本文中のリンクのみ）
- **iOS System Color は彩度が高い** が、Apple は**使う場所を厳しく制限**することで長時間閲覧を成立させている。同じ規律を Manta も守る
