# ワークスペース UI 実行計画

**Status:** Proposal（モック検証中）  
**目的:** 現在の業務機能・状態遷移を変えず、入口・優先順位・視覚文法を段階的に改善する。

## 先に固定すること

1. カルテは [`KARTE_UI_SPEC.md`](KARTE_UI_SPEC.md) の「一本の時系列」「読む・書く・作業する」を守る。
2. 外来・病棟・医事に、手入力する汎用「要確認」「未処理」タスクを新設しない。
3. 状態は原因を持つ既存データから導く。画面では「何が起きているか」と「次に開く対象」を表示する。
4. PlemolJP を標準フォント候補として、まずモックと実機で可読性・全角記号・配信サイズを確認する。
5. 実装前に、デモ表示の各項目をAPI・権限・状態遷移へ一対一で照合する。

## 画面の責務

| 画面 | 入口で扱う事実 | 主作業 | 遷移先 |
|---|---|---|---|
| 外来 | 予約、受付、検査到着、診察中断、患者同定注意 | 患者を選び、診察・記録・オーダーへ入る | カルテ |
| カルテ | 患者同定、安全情報、診療記録、検査、行為 | 読む・書く・オーダーする | 同一時系列内 |
| 病棟 | 病床、未実施指示、看護記録、文書状態 | 指示実施、看護記録、経過・退院文書 | 患者カルテ／病棟詳細 |
| 医事 | 請求ドラフト、未解決の原因、送信状態、返戻 | 原因の解消、レビュー、送信 | ドラフト／カルテ |
| 設定 | 施設ルール、予約枠、テンプレート、監査 | 管理・更新・接続確認 | 設定詳細 |

## 実装順序

### Phase 0 — 照合（変更なし）

- 各モック要素を現在のコンポーネント、API、型、権限へ紐付ける。
- 状態名と導出条件を一覧化する。表示文言を先に確定し、`要確認` のような総称を排除する。
- PlemolJP のライセンス・サブセット化・フォールバック・日本語表示を検証する。

**完了条件:** デモにしか存在しない操作・状態がゼロであること。

### Phase 1 — 共通シェル（低リスク）

- 56px の業務レール、共通TopBar、色・余白・文字トークンを追加する。
- 既存の外来・病棟・医事・設定ルーティングを変えず、外枠だけを共通化する。
- 通常状態は文字と余白、患者安全と破綻状態だけを色で示す。

**完了条件:** 全業務へ戻る操作が一貫し、既存URL・権限・キーボード操作が壊れないこと。

### Phase 2 — 外来ボード（中リスク）

- 受付ボードを「患者の現在状態」中心に再配置する。
- 検査到着、診察一時中断、同姓同名は、患者行内に理由付きで表示する。
- フィルタは `全体 / 自分の担当 / 同じ診療科` を優先し、状態で絞る場合も対象を具体名で示す。

**完了条件:** 各状態から、対象患者と実際の次操作に1クリックで到達できること。

### Phase 3 — カルテ（高リスク）

- 既存 `KARTE_UI_SPEC.md` と `karte-b.html` を正本にして実装する。
- 患者バー、AI一行帯、レンズ、時系列シート、インライン記載、オーダーコンポーザを段階導入する。
- AIは候補・根拠・原本への導線を常に持つ。

**完了条件:** 記載・オーダー・保存・算定プレビュー・患者安全情報が既存と同等以上に動くこと。

### Phase 4 — 病棟・医事・設定（中〜高リスク）

- 共通シェルの文法だけを適用し、病棟の温度板・指示、医事の請求ドラフトの固有作業を平坦化しない。
- 病棟では「未実施指示」「未署名文書」、医事では「明細コード未解決」など、原因を明記する。

**完了条件:** 各画面の専門作業が隠れず、同一の余白・文字・状態表現で読めること。
