# ワークスペース型 UI 再設計案

**Status:** Proposal（2026-07-14）  
**対象:** 外来ホーム・患者カルテを起点に、病棟・医事・設定へ展開するアプリケーションシェル  
**操作モック:** [`mock-html/workspace-prototype.html`](mock-html/workspace-prototype.html)、[`mock-html/operations-workspace-prototype.html`](mock-html/operations-workspace-prototype.html)

## 結論

実装へ入る前に、アプリケーション全体の情報設計を HTML モックで確定する。今回の課題は色や角丸の調整ではなく、ユーザーが「いまどの業務にいて、次に何をするか」を迷わない構造にすることだからである。

参考画面からは、**余白・弱い境界・3ペインの作業空間**という原則だけを学ぶ。画面、コピー、コンポーネントを模写しない。Manta は医療安全、外来・病棟・医事の切替、AI の補助性を第一に独自の導線を設計する。

## 提案する骨格

```text
業務バー         コンテキストペイン       主作業ペイン                 補助ペイン
外来 / 病棟      今日の患者・キュー       患者同定・本日の記載          AI / 検査 / 既往
医事 / 設定      最近開いた患者           経過・オーダー・文書          必要時だけ展開
```

- **業務バー:** Slack のワークスペース切替に相当する常設の細いナビゲーション。外来・病棟・医事・設定を即座に切り替える。患者を開いたままでも、ユーザーは自分の業務上の現在地を失わない。
- **コンテキストペイン:** 「今日診る患者」を中心にしたキュー。検索、担当、診療科、最近開いた患者をここで切り替える。患者を選択してもアプリ全体の文脈は維持する。汎用の「未処理」は置かない。
- **主作業ペイン:** 患者同定、安全情報、本日の記載、オーダーを最上位に置く。カルテのタイムラインは読むための中心だが、AI・入院情報より優先する。
- **補助ペイン:** AI 要約、検査、既往、入院情報など。「常に大きく見せる」のではなく、判断が必要なときに参照できる。閉じても主作業を妨げない。

## 画面ごとの優先順位

### 外来ホーム

1. 今日の患者と、検査到着・診察中断・患者同定などの具体的な状態
2. 患者の状態、予約時刻、担当、短い診療理由
3. 絞り込み・保存済みビュー
4. 最近開いた患者

ホームはダッシュボードではなく、患者へ入るための作業キューとする。集計値や装飾的なカードを先頭に置かない。

### 患者カルテ

1. 患者の取り違えを防ぐ同定情報とアレルギー等の安全情報
2. 「本日の記載」と「オーダー」の主アクション
3. 今日の経過と過去の記録
4. AI 要約・検査・入院等の補助情報

AI は結論を確定しない。要約には根拠を示し、原本へ戻れることを必須とする。

## 視覚ルール

- 基本面は白、キャンバスはごく薄いグレー。カードの乱用を避け、領域分割は余白と 1px の境界を主に使う。
- 本文は 14–15px、補助情報は 12–13px。臨床上の重要な数値と患者同定は小さくしない。
- 色は意味にだけ使う。青は主操作、赤は患者安全上の注意に限定する。完了・安定・AI 補助を色で塗り分けない。
- チップは原則として使わない。短い状態は通常テキスト、オーダーや分類は下線付きテキスト、患者安全上の注意だけを小さなラベルとして区別する。ラベルが並び始めたら、情報の置き場所か優先順位を見直す。
- モバイル縮小ではなく、デスクトップでの高密度な臨床作業をまず最適化する。

## モックで検証すること

1. 業務バーを切り替えたときに、ユーザーが迷わず自分の作業キューへ戻れるか。
2. 患者を切り替えても、本日の記載を始めるまでの操作が短いか。
3. AI・検査ペインを閉じたときも、必要な安全情報が患者ヘッダーに残るか。
4. 外来・病棟・医事が同じシェルを共有しつつ、各々の主作業を邪魔しないか。

## 実装への移行条件

このモックの骨格を確認後、以下の順で React 実装へ移す。

1. アプリケーションシェルと業務バー
2. 外来ホームのコンテキストペイン
3. 患者カルテのヘッダーと本日の記載
4. 補助ペインの開閉・AI 要約の根拠表示
5. 病棟・医事・設定への展開

既存の [`KARTE_UI_SPEC.md`](KARTE_UI_SPEC.md) と [`mock-html/karte-b.html`](mock-html/karte-b.html) は現行方針として保持する。この文書は全面置換の決定ではなく、検証用の次世代シェル提案である。採用する場合は、既存仕様との統合方針を ADR と実装仕様へ反映する。
