Manta · アーキテクチャ概観

どういうレイヤーで、何が動いているのか

Manta は モノレポ + モジュラーモノリス の電子カルテです。カルテを正本に、外部連携（FHIR / ORCA）とレセコンを同じプラットフォームに内包します。 この 1 枚で、システム全体・バックエンドのレイヤー・認証の流れ・機能の成熟度を俯瞰できます。

3認証（JWT）の流れ — 誰がトークンを与えるか

外部 IdP は使わず、Manta 自身のログインエンドポイントが JWT を発行する。利用者アカウントは管理者が作成。

sequenceDiagram
  autonumber
  actor U as 利用者（医師/管理者）
  participant F as フロント（React）
  participant A as auth (/api/auth/login)
  participant R as 保護API (/api/*, /fhir/*)
  U->>F: 利用者 ID + パスワード
  F->>A: ログイン要求
  A->>A: Argon2 照合 → ロール確認 → 期限確認
  A-->>F: JWT を発行（HS256・60分・sub + role）
  Note over F: localStorage(manta-session) に保存
  F->>R: 各リクエストに Authorization ヘッダで JWT を送る
  R->>R: 署名（MANTA_JWT_SECRET_KEY）と期限を検証 → 利用者を解決
  R-->>F: データ（無効/欠落トークンは 401）
発行元： Manta backend（create_access_token） 署名鍵： MANTA_JWT_SECRET_KEY（本番で既定値なら起動を拒否） 権限： 管理者限定 API は require_role("管理者")

現状の限界：リフレッシュトークン無し（60 分で失効 → 再ログイン）、失効リスト無し、ログイン失敗ロックは未実装。将来は外部 IdP 連携も差し込み可能。

4データの流れ — カルテが正本、会計は派生

会計・レセプトはカルテ／オーダ／病名から導く派生データ。AI は候補生成のみで、確定は必ず人間。

5機能の成熟度

「動く／一部／デモ」を色で区別。デモ（🟠）には見せかけ表示を含むため、UI 上でもその旨を明示しています。

外来カルテ🟢 動くドキュメント型 UI・SOAP 版管理・下書き自動退避・オーダ・処方コピー・PMDA 相互作用警告・次回予約
受付ボード🟢 動く外来 / 入院ビュー・検索 / フィルタ・最近開いたカルテ

レセコン🟡 一部入院 claim draft・施設別ルール DSL・返戻 / 査定・月次クローズ → 外来レセ・点数計算・レセ電(UKE)生成
